title: Guarantees
description: Exact rate bounds, pause propagation, queue ordering, and failure behavior.
---

Bounds describe the total **cost of jobs started**, on the store clock.
They do not describe job completion times or the provider's own accounting.

| Rule                     | Bound                                                                              |
| ------------------------ | ---------------------------------------------------------------------------------- |
| GCRA                     | At most `limit + burst - 1` units in any half-open interval of length `interval`.  |
| GCRA, default `burst: 1` | At most `limit` units per interval, spaced by `interval / limit`.                  |
| Fixed window             | At most `limit` units in each aligned `[k * interval, (k + 1) * interval)` window. |
| Several rules            | Each rule holds independently. The store checks and updates them atomically.       |
| Local concurrency        | At most `concurrency` jobs running in one valve instance.                          |

Fixed windows can admit up to `2 * limit` units near an adjacent-window
boundary. Use them when that matches the provider's quota.

## Shared pauses

After a pause is written, subsequent acquires grant no jobs until it expires.
A grant issued before the pause can still start. A pause only extends the
existing pause. `resume()` deletes it.

Each process caches a known pause to avoid repeated store calls. Another
process's resume is seen on its next store call, which may be at the end of
that cached pause. Pass a dedicated `subscriber` to `redisStore` to wake
waiting processes through pub/sub after pause, resume, and slot release.
Memory-store instances notify their listeners directly. Notifications are
hints: the store still checks every admission atomically. Missed Redis
notifications fall back to normal acquisition and pause-expiry checks.

`observe()` writes a pause in the background and returns immediately. A
failed write emits `store-error` and is not retried. Use `await pause(...)`
when you need acknowledgement that the store recorded a pause.

## Grants and cancellation

A job cancelled while its acquire is in flight does not run. Its already
issued grant is spent and is not reused. A timed-out Redis call can also
consume budget even if its late result is ignored. These cases reduce use;
they do not increase the allowed rate.

## Ordering and concurrency

Inside one valve, higher priorities start first and ties preserve call order.
Fetch retries retain their original sequence. A batch already submitted to
the store can receive grants before a newly arrived higher-priority job.
Across processes, there is no ordering or fairness guarantee.

Concurrency counts jobs, not cost units. A number or `{ limit, scope: 'local' }`
limits one valve instance. `{ limit, scope: 'global', leaseTtl: '30s' }` uses
shared leases in the store, acquired atomically with the rate rules.
Use matching limits and TTLs for every valve sharing an id.

A lease is renewed every `leaseTtl / 3` while its job runs and released when
the job settles. A crashed worker's slots expire. If renewal fails or a lease
expires, the job's context signal aborts and its result rejects with
`LEASE_LOST`. `wrapFetch` forwards this signal to the HTTP client.

Leases bound live ownership, not uninterruptible external work. A process
paused longer than its TTL can resume after its slot was reassigned. Jobs
must honor the abort signal; use external fencing if your system needs a
strict bound even during process stalls or network partitions. Memory-store
global scope shares only instances using that same store in one process.

Without a subscriber, global-slot waiters poll at most every 50ms, plus
scheduler jitter, so a released slot can be reused before its former TTL.

## Store failure and process failure

The default `onStoreError: 'wait'` keeps jobs queued and retries with backoff,
while respecting `maxWait`. `throw` rejects affected jobs. `open` starts jobs
without enforcing shared rate rules while the store is down, so the rate
bounds above do not hold during that period. Global concurrency rejects
`onStoreError: 'open'` to avoid bypassing lease ownership.

Queued jobs are held in memory. Process death loses queued work. A store
restart that loses budget state permits a fresh budget; persistent store
configuration is the application's responsibility. Use a durable job queue
when work must survive a restart.

Rate bounds are measured at atomic store admission. A delayed callback or network
write can occur later, so actual HTTP arrival times may bunch together.
