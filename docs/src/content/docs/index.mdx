valve puts a shared budget in front of your outbound API calls. Every process
using the same valve id and Redis store draws from that budget. When a provider
asks you to slow down, every worker sharing it pauses.

<SharedBudget />

```ts
import { createValve } from '@ksaurav24/valve';
import { redisStore } from '@ksaurav24/valve/redis';

const api = createValve({
  id: 'partner:credential-42',
  rate: { limit: 100, interval: '1s' },
  store: redisStore({ client: redis }),
});
const limitedFetch = api.wrapFetch();
const response = await limitedFetch('https://api.example.com/contacts');
```

## Start with the guarantee you need

The default GCRA rule spreads starts evenly, with `burst: 1`. A fixed-window
rule spends at most its limit in each aligned window. Combine rules when the
provider has both short and long quotas.

## What 0.1.0 includes

Memory and Redis/Valkey stores, atomic checks across several rules, local
concurrency, priorities, job cost, cancellation, queue deadlines, provider
feedback, and fetch retries for rate limit responses.

Concurrency is local. Queued jobs live in the process and do not survive a
restart. Postgres, global concurrency, presets, and durable jobs are not part
of this version.

This repository is private while the implementation is prepared. Version
0.1.0 has not been published to npm.
