Valve queues outbound API calls until the configured rate and concurrency
limits allow them to run. Use the default memory store for a single process,
or Redis or Valkey to share a budget across workers.

If a provider meters usage per credential, separate per-process limits can
exceed that shared quota. Workers using the same Valve ID and shared store
check and spend one budget. Provider response headers can also establish a
cooldown for all workers sharing that budget.

```ts
import { createValve } from 'valvejs';
import { redisStore } from 'valvejs/redis';

const hubspot = createValve({
  id: 'hubspot:portal-123',
  rate: { limit: 190, interval: '10s' },
  store: redisStore({ client: redis }),
});

const limitedFetch = hubspot.wrapFetch();
const response = await limitedFetch(
  'https://api.hubapi.com/crm/v3/objects/contacts',
);
```

Valve is in beta. APIs may change before 1.0. See [Installation](/docs/installation/)
for package requirements and setup.

## What valve does

- Check and spend several rate rules atomically on the store's clock. Redis
  admission uses a Lua script.
- Queue jobs locally with priorities, cost, concurrency limits, queue bounds,
  deadlines, and abort signals.
- Read `Retry-After`, IETF `RateLimit`, and common `x-ratelimit-*` headers to
  pause workers sharing the budget.
- Retry eligible rate limit responses through `wrapFetch`. Each retry returns
  to the queue and acquires a new grant.
- Update named managed rules at runtime, preserving spent budget while changing
  `limit` and GCRA `burst`.

The package has no runtime dependencies and ships ESM, CommonJS, and TypeScript
declarations. You supply and manage any `ioredis` or `node-redis` connections.

## When to use it

| You need to                                              | Use                                                   |
| -------------------------------------------------------- | ----------------------------------------------------- |
| Respect a provider quota shared by several processes     | valve with the Redis store                            |
| Space calls from a single script or service              | valve with the default memory store                   |
| Limit parallel work inside one process, with no quota    | `p-limit` or `p-queue`                                |
| Accept or reject **inbound** requests to your own server | An inbound rate limiter                               |
| Keep jobs across process restarts                        | A durable job queue, with valve around outbound calls |

valve limits when calls **start**. It does not persist queued jobs, retry
arbitrary failures, or act as a circuit breaker.
