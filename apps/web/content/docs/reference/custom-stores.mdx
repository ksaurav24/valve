---
title: Custom stores
description: The Store interface, for backends other than memory and Redis.
---

A store keeps rule state, the shared pause, and global leases. valve ships a
memory store and a Redis store. Implement `Store` to add another backend.

```ts
import type { Store } from 'valvejs';
```

## Interface

| Member                      | Required | Description                                                                                     |
| --------------------------- | -------- | ----------------------------------------------------------------------------------------------- |
| `kind`                      | Yes      | Short name used in messages, such as `'memory'` or `'redis'`.                                   |
| `acquire(request)`          | Yes      | Atomically checks the pause and every rule, then grants a prefix of `costs`.                    |
| `acquireSync?(request)`     | No       | Synchronous version. Used on the hot path when present.                                         |
| `pause(id, durationMs)`     | Yes      | Extends the pause to at least `durationMs` from now. Never shortens it.                         |
| `resume(id)`                | Yes      | Removes the pause.                                                                              |
| `release?(id, leases)`      | Global   | Releases global concurrency slots when jobs settle.                                             |
| `renew?(id, leases, ttlMs)` | Global   | Renews unexpired slots. Returns `false` if any was lost. Never revives expired ones.            |
| `subscribe?(id, listener)`  | No       | Notifies of pause, resume, release, and managed-limit commits. Returns an unsubscribe function. |
| `close()`                   | Yes      | Frees resources owned by the store. Never closes user-provided clients.                         |

`release` and `renew` are required for `concurrency: { scope: 'global' }`.

## acquire

```ts
interface AcquireRequest {
  readonly id: string;
  readonly rules: readonly NormalizedRule[]; // Empty for a concurrency-only valve.
  readonly costs: readonly number[]; // Head of the queue, in order. Never empty.
  readonly lease?: {
    readonly limit: number;
    readonly ttlMs: number;
    readonly owner: string;
  };
}

interface AcquireResult {
  readonly granted: number; // Jobs granted, counted from the start of costs.
  readonly retryAfterMs: number; // If not all were granted and not paused: ms until the next could be.
  readonly pausedMs: number; // Ms left on an active pause. When above 0, granted is 0.
  readonly leases?: readonly string[]; // One unique token per grant when lease was requested.
  readonly leaseBlocked?: boolean; // With a lease: true if full slots, not a rate rule, denied the first ungranted job.
}
```

Each `NormalizedRule` carries `algorithm`, `limit`, `intervalMs`, `burst`, and
a stable `key`: `${algorithm}:${intervalMs}` for unnamed rules or
`named:${name}` for named rules. Named and scoped rules also carry `name` and
`scope` when configured.

Set `leaseBlocked` on results for lease requests. Valves poll lease waits at a
short interval but wait out rate denials for the full `retryAfterMs`. A store
that omits it is treated as lease-blocked.

## Requirements

- **Atomicity.** Checking the pause, checking every rule, spending cost, and
  acquiring leases must happen as one indivisible step across all processes.
- **One clock.** All time math must use the store's own clock, never the
  caller's.
- **Prefix grants.** Grant jobs strictly in order. Stop at the first job that
  does not fit.
- **No partial spends.** If a job does not fit one rule, spend nothing for it
  in the others.
- **Pinned policy.** Reject a request with `INVALID_OPTIONS` when its rules,
  lease limit, or lease TTL differ from the policy other workers use for the id.
- **Finite retry hints.** When more jobs ask for leases than slots are free,
  return a finite `retryAfterMs`, such as the lease TTL when no slot is held.

The memory store's source, `packages/valve/src/memory-store.ts`, is a compact
reference implementation. The Redis Lua scripts in `packages/valve/src/redis/`
show the same logic for a remote backend.

## Scoped admission capability

Existing stores can keep implementing `acquire` for static configurations.
Scoped rules require the optional `acquireScoped(request)` method; creation
rejects unsupported stores. Exported `ScopedAcquireRequest` and
`ScopedAcquireResult` describe this contract:

```ts
interface ScopedAcquireResult {
  grantedIndexes: readonly number[];
  pausedMs?: number; // Ms left on an active pause. When above 0, every job is blocked.
  blocked: readonly {
    index: number;
    retryAfterMs: number;
    leaseBlocked?: boolean; // With a lease: true if full slots set the retry hint.
  }[];
  leases?: readonly { index: number; token: string }[];
}
```

The request contains `id`, immutable normalized `rules`, ordered `jobs` with
`cost` and `scopes`, and optional `lease` settings. Indexes are zero-based into
`jobs`. Every job must appear exactly once in grants or denials. Retry hints
must be positive safe integers. Report an active shared pause in `pausedMs` so
valves without a subscriber can show it in `stats()` and emit `pause`. Global
requests need one unique lease token per admitted index, released and renewed
through the existing methods.

Validate the complete request before mutation. Use one store clock and one
atomic operation to check the shared pause, every applicable rule, and lease
capacity. A denial spends nothing; continue evaluating later jobs, including
lower-cost jobs. Deduplicate keys and update temporary state after each grant
so repeated identities see earlier admissions in the same batch. Commit only
final changed states. Pin the complete policy independently of expiring rate
state and reject incompatible workers.

Requests contain at most 16 rules and 128 jobs. `acquireScopedSync` is an optional
synchronous optimization with the same semantics. Do not implement scoped
admission as repeated calls to `acquire`: separate reservations cannot enforce
all-or-none spending. See [Scoped rate limits](/docs/guides/scoped-rate-limits/)
for identity requirements and operational limits.

## Managed limits capability

Set `store.managed` only when the store implements the complete version 1
contract. Partial implementations are unsupported.

```ts
interface ManagedStore {
  readonly version: 1;
  acquire(request: ManagedAcquireRequest): Promise<ManagedAcquireResult>;
  acquireSync?(request: ManagedAcquireRequest): ManagedAcquireResult;
  acquireScoped?(request: ManagedScopedRequest): Promise<ManagedScopedResult>;
  acquireScopedSync?(request: ManagedScopedRequest): ManagedScopedResult;
  getLimits(context: ManagedContext): Promise<LimitsSnapshot>;
  updateLimits(request: ManagedUpdateRequest): Promise<LimitsSnapshot>;
}
```

`limits: 'managed'` requires `acquire`, `getLimits`, and `updateLimits`.
Managed scoped configurations also require `acquireScoped`; synchronous methods
are optional hot-path optimizations.

The request's normalized rule values are registration seeds, not admission
authority. Atomically register absent state or verify existing state, then read
the stored limits and decide admission against those values in the same
transaction. Pin names, scopes, algorithms, intervals, the static/scoped shape,
and global lease configuration. Accept different numeric `limit` and `burst`
seeds after registration, but return `INVALID_OPTIONS` for structural mismatch
or incompatible immutable state before mutating anything.

Preserve fixed-window counts and alignment across updates. For GCRA, preserve
debt in cost units while changing its drain rate; a burst update changes the
capacity threshold without erasing debt. Validate patches and expectations
atomically, create no revision for a no-op, and return `LIMITS_CONFLICT` without
changes when an expectation fails. A snapshot version must distinguish both a
new registration epoch and every committed revision.

Managed results can include a `limits` snapshot when its version differs from
the request's `known` token. Static results set `impossible` only when the first
ungranted job exceeds current capacity. Scoped blocked entries set
`impossible` per job. A pause or full global lease set takes precedence over
that classification.

After a commit, publish `{ type: 'limits', version, relaxed }`, where `relaxed`
is true when any `limit` or `burst` increased. Notices are wake-up hints only;
correctness must not depend on delivery. Valve periodically calls `getLimits`
during long waits even without a subscriber.

Scoped GCRA state may require lazy per-identity migration rather than a scan.
If a slower rate cannot extend the expiry of untouched live identities, document
the early-expiry bound described in the
[runtime limits guide](/docs/guides/runtime-limits/#update-scoped-limits).
