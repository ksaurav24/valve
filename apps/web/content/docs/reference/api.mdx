## createValve

```ts
function createValve(options: ValveOptions): Valve;
```

Creates a valve. Throws `ValveError` with code `INVALID_OPTIONS` if an option
is invalid. At least one of `rate` or a finite `concurrency` is required.

### ValveOptions

| Option         | Type                                  | Default                      | Description                                                                                                    |
| -------------- | ------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `id`           | `string`                              | Required                     | Name of the shared budget. 1 to 200 characters, without `{` or `}`.                                            |
| `rate`         | `RateRule \| RateRule[]`              | None                         | One rule, or a non-empty array of rules.                                                                       |
| `concurrency`  | `number \| ConcurrencyOptions`        | `Infinity`                   | A number limits this instance. The object form can select global scope.                                        |
| `store`        | `Store`                               | A new private memory store   | Where the shared budget lives.                                                                                 |
| `maxQueue`     | `number`                              | `Infinity`                   | Maximum jobs waiting in this process. Beyond it, `run` rejects with `QUEUE_FULL`.                              |
| `maxWait`      | `Duration`                            | No limit                     | Maximum time a job may wait before starting.                                                                   |
| `feedback`     | `Feedback \| false`                   | `defaultFeedback`            | Reads provider responses. `false` disables header reading.                                                     |
| `maxPause`     | `Duration`                            | `'15m'`                      | Cap on any one pause caused by feedback or backoff.                                                            |
| `backoff`      | `{ base?: Duration; max?: Duration }` | `{ base: '1s', max: '30s' }` | Exponential pause after a 429 with no usable header.                                                           |
| `onStoreError` | `'wait' \| 'throw' \| 'open'`         | `'wait'`                     | Behavior when the store fails. See [Store failures](/docs/guarantees/#store-failures).                         |
| `limits`       | `'immutable' \| 'managed'`            | `'immutable'`                | Store-authoritative runtime values when managed. See [Update limits at runtime](/docs/guides/runtime-limits/). |
| `batch`        | `number`                              | `32`                         | Maximum jobs requested from the store in one call.                                                             |

### RateRule

| Field       | Type                       | Default  | Description                                                     |
| ----------- | -------------------------- | -------- | --------------------------------------------------------------- |
| `name`      | `string`                   | None     | Stable rule identity; required for scoped rules.                |
| `scope`     | `string`                   | None     | Job identity dimension; absent means Valve-wide.                |
| `limit`     | `number`                   | Required | Cost units allowed per `interval`. Positive integer.            |
| `interval`  | `Duration`                 | Required | Window length. At least 1ms.                                    |
| `burst`     | `number`                   | `1`      | Units that may start back to back. GCRA only. Positive integer. |
| `algorithm` | `'gcra' \| 'fixed-window'` | `'gcra'` | See [Choose an algorithm](/docs/choosing-an-algorithm/).        |

Unnamed rules cannot share the same `algorithm` and `interval`. Set a unique
`name` to distinguish rules with matching algorithms and intervals. Scoped rules
require names and select a job identity through `scope`. Both fields accept
1-64 ASCII letters, digits, underscores or hyphens, beginning with a letter.
See [Scoped rate limits](/docs/guides/scoped-rate-limits/). Scoped configurations
support at most 16 rules and batch 128 (default 32).

With `limits: 'managed'`, at least one rate rule is required and every rule
must have a name. The configured `limit` and GCRA `burst` seed a new store
registration; stored values are authoritative after registration. Rule names,
scopes, algorithms, intervals, and global concurrency remain fixed.

### ConcurrencyOptions

| Field      | Type                  | Default   | Description                                                      |
| ---------- | --------------------- | --------- | ---------------------------------------------------------------- |
| `limit`    | `number`              | Required  | Maximum running jobs. Positive integer.                          |
| `scope`    | `'local' \| 'global'` | `'local'` | `'global'` shares the limit across every valve with the same id. |
| `leaseTtl` | `Duration`            | `'30s'`   | Global lease lifetime, renewed every third. Minimum 30ms.        |

Global scope requires a store that implements `release` and `renew`. Both
built-in stores do.

### Duration

A number of milliseconds, or a string ending in `ms`, `s`, `m`, or `h`.
Decimals are allowed.

```ts
250; // 250 ms
('1.5s'); // 1500 ms
('10m'); // 600000 ms
('24h'); // 86400000 ms
```

Negative values, `NaN`, `Infinity`, and unknown units are rejected.

## Valve

### run

```ts
run<R>(fn: (ctx: JobContext) => R, options?: RunOptions<Awaited<R>>): Promise<Awaited<R>>
```

Queues `fn` and calls it when every rule and the concurrency limit allow.
Resolves or rejects with whatever `fn` returns or throws. `fn` receives
`{ signal }`, the signal from `options.signal` (or the lease signal under
global concurrency). `run` never throws synchronously, and never calls `fn`
synchronously.

#### RunOptions

| Option     | Type                                    | Default         | Description                                                     |
| ---------- | --------------------------------------- | --------------- | --------------------------------------------------------------- |
| `scopes`   | `Readonly<Record<string, string>>`      | None            | Required identities for scoped rules; copied before enqueueing. |
| `cost`     | `number`                                | `1`             | Units spent from every rule.                                    |
| `priority` | `number`                                | `0`             | Higher starts first. Integer.                                   |
| `maxWait`  | `Duration`                              | Valve `maxWait` | Queue deadline for this job.                                    |
| `signal`   | `AbortSignal`                           | None            | Cancels the job while queued. Passed to `fn` once running.      |
| `observe`  | `(result) => ResponseLike \| undefined` | None            | Maps a resolved result to a response for feedback.              |

### wrap

```ts
wrap<A extends unknown[], R>(fn: (...args: A) => R, options?: Omit<RunOptions, 'signal'>): (...args: A) => Promise<Awaited<R>>
```

Returns a function with the same parameters as `fn`. Each call goes through
the valve with `options`.

### wrapFetch

```ts
wrapFetch<F extends FetchLike = typeof fetch>(fetchImpl?: F, options?: WrapFetchOptions<F>): F
```

Returns a function with the same type as `fetchImpl` (default
`globalThis.fetch`). It queues each request, observes each response, and
retries eligible rate limit responses for GET, HEAD, OPTIONS, PUT and DELETE
by default. See [Respect provider feedback](/docs/guides/respect-retry-after/#with-fetch).

#### WrapFetchOptions

| Option               | Type                                                                                | Default         | Description                                                                             |
| -------------------- | ----------------------------------------------------------------------------------- | --------------- | --------------------------------------------------------------------------------------- |
| `scopes`             | `Readonly<Record<string, string>> \| (...args) => Readonly<Record<string, string>>` | None            | Fixed identities or a synchronous resolver, snapshotted once across retries.            |
| `retries`            | `number`                                                                            | `2`             | Retries after a 429, or a 503 with a valid `Retry-After`. `0` disables.                 |
| `retryUnsafeMethods` | `boolean`                                                                           | `false`         | Opt in to retries for other methods after verifying provider-specific idempotency.      |
| `maxReplayBodySize`  | `number`                                                                            | `65536`         | Finite integer byte limit for inherited Request replay. `0` sends once without probing. |
| `cost`               | `number \| (...args) => number`                                                     | `1`             | Cost per request, or a function of the fetch arguments.                                 |
| `priority`           | `number \| (...args) => number`                                                     | `0`             | Priority per request, or a function of the fetch arguments.                             |
| `maxWait`            | `Duration`                                                                          | Valve `maxWait` | Queue deadline for each attempt.                                                        |

The request's abort signal, from `init.signal` or the `Request`, cancels queued
attempts and is passed to `fetchImpl` for running ones.
It also cancels a running Request body probe before fetch begins.

`retries` counts additional attempts after the initial request. The default of
`2` permits up to three total requests. Once the retry limit is exhausted, the
final response is returned unchanged.

`init.method` overrides the `Request` method; otherwise the method defaults to
GET. POST, PATCH and unrecognized methods do not retry unless
`retryUnsafeMethods: true`. A supplied idempotency key does not opt in.
All responses still update shared cooldowns. Streamed `init.body` requests
never retry, including with the opt-in enabled. Use a dedicated wrapper for
verified operations; see the [compatibility notes](/docs/guides/respect-retry-after/#requests-with-side-effects).

Inherited `Request` bodies retry only if a probe clone fits within
`maxReplayBodySize`. Probing occurs after admission, holds the concurrency
slot, and delays upload until the body ends or exceeds the limit. Larger
bodies and bodies exceeding 1,024 chunks are sent once. Empty chunks count
toward this second limit. The probe can retain the limit plus one source chunk
and stream prefetch. Set `maxReplayBodySize: 0` to skip probing and send
Request bodies once. Explicit `init.body` overrides bypass probing of the
unused body. See [Request bodies](/docs/guides/respect-retry-after/#request-bodies).

### observe

```ts
observe(response: ResponseLike): void
```

Reads a response with the valve's feedback reader. If it asks for a pause,
writes a shared pause in the background. Safe to call with any response.

### pause

```ts
pause(duration: Duration): Promise<void>
```

Pauses the valve in every process sharing it. Only extends an existing pause.
Resolves once the store records it. Not capped by `maxPause`.

### resume

```ts
resume(): Promise<void>
```

Ends the current pause in every process sharing the valve.

### getLimits

```ts
getLimits(): Promise<LimitsSnapshot>
```

Reads the store's authoritative managed limits, registering this valve's seeds
if the store has no values for the ID. Rejects with `INVALID_OPTIONS` on an
immutable valve and `STORE_UNAVAILABLE` on store failure.

### updateLimits

```ts
updateLimits(
  patch: LimitsPatch,
  options?: { expect?: LimitsPatch },
): Promise<LimitsSnapshot>
```

Atomically sets absolute `limit` and GCRA `burst` values by rule name. Omitted
rules and fields stay unchanged. A no-op returns the same version. Without
`expect`, the same field is last-writer-wins. Expected fields must equal the
current value or already equal their patched value; otherwise nothing changes
and the call rejects with `LIMITS_CONFLICT`.

Validation rejects unknown rules or fields, values that are not positive safe
integers, `burst` on fixed-window rules, and immutable valves with
`INVALID_OPTIONS`. A store failure becomes `STORE_UNAVAILABLE`; its outcome can
be unknown, and repeating the same absolute patch is safe. See
[Update limits at runtime](/docs/guides/runtime-limits/) for debt, concurrency,
scoped, and deployment semantics.

### Managed limit types

```ts
type LimitsPatch = Readonly<
  Record<string, { readonly limit?: number; readonly burst?: number }>
>;

interface LimitsSnapshot {
  readonly version: string;
  readonly revision: number;
  readonly rules: Readonly<Record<string, LimitsRule>>;
}

interface LimitsRule {
  readonly algorithm: 'gcra' | 'fixed-window';
  readonly intervalMs: number;
  readonly limit: number;
  readonly burst: number;
  readonly scope?: string;
}
```

`version` is opaque. `revision` starts at 1 for a registration and can restart
after store state loss. Fixed-window snapshots always report `burst: 1`.

### stats

```ts
stats(): ValveStats
```

Returns a snapshot for this process. See [Monitor a valve](/docs/guides/observability/#export-queue-metrics).

### on

```ts
on<E extends keyof ValveEventMap>(event: E, listener: (payload: ValveEventMap[E]) => void): () => void
```

Adds a listener and returns a function that removes it. See
[Events](/docs/reference/events/).

### idle

```ts
idle(): Promise<void>
```

Resolves when nothing is queued or running in this process.

### close

```ts
close(options?: { drain?: boolean }): Promise<void>
```

Stops accepting jobs. Without `drain`, queued jobs reject with `CLOSED`. With
`drain: true`, they run first. Resolves when running jobs finish. Repeated
calls return the same promise. Never closes a client you supplied.

Valves also implement `[Symbol.asyncDispose]`, which calls `close()`.

### id

```ts
readonly id: string
```

The id passed to `createValve`.

## runSequential

```ts
function runSequential<R>(
  stages: readonly SequentialStage<Awaited<R>>[],
  fn: (ctx: JobContext) => R,
  options?: RunSequentialOptions,
): Promise<Awaited<R>>;
```

Runs `fn` after each valve admits it in turn, outermost first. It is
equivalent to `a.run(() => b.run(fn))`, with each stage's own options. It is
**not atomic**: an earlier stage's admission stays spent when a later stage
rejects, times out, is aborted, or is closed, and nothing is refunded. See
[Compose valves](/docs/guides/compose-valves/).

### SequentialStage

| Field     | Type                         | Description                                                                                  |
| --------- | ---------------------------- | -------------------------------------------------------------------------------------------- |
| `valve`   | `Valve`                      | The valve that admits this stage. Every stage needs a different `id`.                        |
| `options` | `Omit<RunOptions, 'signal'>` | Options for this stage only: `scopes`, `cost`, `priority`, `maxWait`, `observe`. Not shared. |

### RunSequentialOptions

| Option   | Type          | Description                                                         |
| -------- | ------------- | ------------------------------------------------------------------- |
| `signal` | `AbortSignal` | Passed to every stage's `run` and to `fn` through its `JobContext`. |

### Rejections

`runSequential` never throws synchronously. It rejects with `INVALID_OPTIONS`,
before any stage admits, for an empty or non-array `stages`, a stage without a
valve, a non-function `fn`, or two stages with the same valve `id`. Otherwise
it settles with whatever `fn` settles with, or rejects with the first stage
rejection, whose `valveId` names that stage. An inner stage rejection
propagates as the outer job's failure, so the outer valve counts it as failed,
not rejected. The helper never closes a valve or store and never calls
`observe` itself.
